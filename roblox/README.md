# Roblox integration (Rojo)

This folder syncs the whole animation pack into Roblox Studio with [Rojo](https://rojo.space): all 25 KeyframeSequences, a replacement `Animate` script, combat, chat emotes, crouch, and a test arena.

> Quick start only. A full step-by-step tutorial comes later.

## Quick start

1. Install Rojo 7: the CLI (via [Aftman](https://github.com/LPGhatguy/aftman), Foreman or a release binary) and the Rojo Studio plugin.
2. In the repo root, run:
   ```bash
   rojo serve            # serves default.project.json
   ```
3. In Studio, open a new **Baseplate**, click **Rojo → Connect**, then press **Play**.
4. In Studio, every clip loads straight from its synced KeyframeSequence, so nothing needs publishing to test.
   Those temporary IDs only work on the machine that registered them. So clips the *server* starts (the dummy's idle and death, hit reactions) are relayed to clients through `ReplicatedPlay`, `Remotes.PlayAnimation` and `AnimationReplicator`, which play them locally.
   Once the clips are published, the server plays them directly and the Animator replicates them.

### The Animate script

- Uses idle, walk or run depending on speed. Run starts at 8.5 studs/s. Walk and run playback is scaled to the ground speed they were animated for, up to 3.5×.
- Plays jump, then blends into fall.
- Plays climb (frozen when you hang still), swim or swim_idle, sit, and death.
- **C** or **Left Ctrl** toggles crouch and uses crouch_idle and crouch_walk. Crouch WalkSpeed is set from the speed crouch_walk was animated for (×3), about 2.7 studs/s, so the feet don't slide. It's a slow sneak; raise `CROUCH_CYCLE_RATE` if you want it faster.
- Chat emotes: `/e wave`, `dance`, `cheer`, `point`, `laugh`, `clap`, `salute`, or `/emote …`. Under TextChatService, the built-in `RBXEmoteCommand` is replaced locally so the pack's own emotes work. Moving or crouching cancels them.
- Another script can trigger an emote by invoking the `PlayEmote` BindableFunction under the Animate script.

### Combat feel

- Hits get a contact flash, a sound, a damage number and a short hit-stop. Heavy hits (combo finisher, kick, sword) also knock the target back. The kick launches people, for example off the tower.
- Blocking shows BLOCKED with a clang. Raising the guard within 0.25 s before a hit is a **parry**: no damage, and the attacker staggers. One parry is possible per guard raise, at most once a second.
- Crouch plus a hit from behind is a **sneak attack** for double damage. It's checked on the server, including real crouch speed.
- The combo's third hit is a **guard break**: it goes through block and parry and drops the guard. The kick works with or without the sword.
- The 3 s spawn shield blocks all hits and shows SHIELDED. Attacking ends your own shield.

### Social and goals

- `/e highfive`: two players within 7 studs within 3 s get a synced high five. Alone, you're "left hanging".
- Dancing next to a friend syncs your dance, and two dancers start a "Dance party!".
- Any emote within 8 s of a KO is a taunt in the kill feed. An unknown `/e` shows the list of emotes, and an emote that can't play right now says why.
- **Records board:** fastest climb (start pad to bell), biggest splash (fall height into the pool, checked against the server's height tracking), 10 s dummy damage challenge (orange pad), total high fives, and head-to-head **rivalries**. The first player to 5 KOs on a rival **wins the set**: a callout for everyone and an automatic cheer, and the set count goes on the board. Dummy kills appear in the feed but don't count as KOs.

### Test arena

In Studio, `TestArena` builds:
- a spawn shield, plus a controls sign and the records board facing spawn
- a truss with the climb race
- a water pool with a splash zone
- a bench with a **launch lever** that flings the sitter into the pool, with a different height and landing spot each time; being knocked into the pool is a **dunk** in the feed
- a respawning R15 training dummy with a visible health bar, which walks back home after being kicked away
To build it in live games too, set the attribute `BuildTestArena = true` on `ReplicatedStorage.AnimationPack`.

## Publishing for a live game

The KeyframeSequence fallback only works in Studio. For a published game:

1. In Studio, open the **Animation Editor** and select an R15 rig (e.g. Avatar → Rig Builder → R15).
2. For each clip in `ReplicatedStorage.AnimationPack.KeyframeSequences`, load it (⋯ → Load, or right-click the KeyframeSequence → Save to Roblox), then use **Publish to Roblox**.
3. Paste each asset ID into `src/shared/AnimationIds.luau`. Rojo syncs the change.

Notes:

- Animations must be owned by the game's owner (user or group), or they won't play in that game.
- `death` needs `Humanoid.BreakJointsOnDeath = false`. `CombatServer` sets this for players, and the test dummy has it too.

## Regenerating

After changing animations in the Blender pipeline:

```bash
python -m pipeline.export              # rewrites output/rbxmx/*.rbxmx and src/shared/AnimationMeta.luau
python roblox/check_project.py         # offline consistency check of this project
```
